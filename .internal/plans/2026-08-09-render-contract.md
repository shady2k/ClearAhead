# Контракт отрисовки и типы путевых конструкций — план реализации

> **Для агентов-исполнителей:** ОБЯЗАТЕЛЬНЫЙ САБ-СКИЛЛ:
> beads-superpowers:subagent-driven-development или executing-plans.

**Goal:** Убрать инженерные правила из клиента в контракт: типы путевых
конструкций, рецепт размещения и канонические особенности устройств приходят с
сервера, клиент только рисует.

**Спека:** `.internal/specs/2026-08-09-render-contract-and-types-design.md`
(редакция 5, согласована). Она — источник истины по форме; здесь только порядок
работ и границы.

**Архитектура:** Три уровня — рецепт для регулярного, канонические позы для
особенностей устройств, разреженные переопределения потом. Граница
ответственности по авторитетности: сервер владеет фактами, клиент изображением.

## Глобальные ограничения

- Форма полей — строго по спеке. Расхождение с ней это дефект, а не улучшение.
- `format_version` карты поднимается до 2, `ST_A` — минимум до ревизии 3: тело
  `/revisions/2/geometry` уже отдано как immutable.
- Все новые массивы сортируются канонически: типы по `id`, run'ы по `id`,
  особенности по `(owner, kind, addresses)`; спаны внутри run — в авторском
  порядке.
- Провод не имеет версии схемы, `contract_test.go` декодирует с
  `DisallowUnknownFields` — значит обновление обеих сторон и эталона
  **атомарное, одним изменением**.
- Не коммитить, не пушить, не трогать `bd`.

## Волна 2a — сервер

### Task 1: Блок `construction` в формате карты

**Файлы:** изменить `mapfmt/schema.go`; создать `mapfmt/construction.go`;
тест `mapfmt/construction_test.go`.

**Produces:** `type Construction struct`, `type TrackType struct`,
`type ConstructionRun struct`, `func (m *Map) validateConstruction() error`.

**Критерии приёмки:**
- Форма ровно как в спеке §3: `default_type`, `types[]`, `runs[]`.
- Тип несёт `gauge`, `sleeper{pitch,length,width}`, `ballast{half_width}`.
  Полей `shoulder_slope` и `sleeper.type` НЕТ — они сознательно не заводятся.
- Run несёт `id`, `type` (необязателен), `coordinate` (только `"u"`), `phase`,
  `spans[]{element,from,to,direction}`.
- Валидация: все величины конечны и строго положительны; `id` уникальны; ссылка
  на неизвестный тип — отказ; `0 ≤ phase < pitch`; `coordinate` только `"u"`.
- **Покрытие рёбер полное, без пропусков и перекрытий** — отказ иначе.
- Проходы устройств run'ами НЕ покрываются; устройство несёт собственный `type`.
- Отказ начинается с префикса `отрисовка: `.

### Task 2: Диапазоны, а не только знак

**Файлы:** изменить `mapfmt/construction.go`, `mapfmt/limits.go`.

**Критерии приёмки:**
- У каждого нового массива есть лимит длины (типы, run'ы, спаны в run).
- У каждой величины типа есть **правдоподобный диапазон**, а не только проверка
  знака: шаг шпал 0.001 м проходит «строго положительно» и даёт 1.8 млн шпал на
  километр — клиент ложится без ошибки.
- Красная карта на шаг шпал вне диапазона (положить в `mapfmt/testdata/`, файл
  назвать так, чтобы не столкнуться с корпусом соседней волны:
  `construction_pitch_out_of_range.json`).

### Task 3: Типы и run'ы уезжают в контракт

**Файлы:** изменить `track/compile.go`, `track/hash.go`.

**Produces:** поля `track_types`, `construction_runs`, `placement_algorithm` в
`RenderGeometry`.

**Критерии приёмки:**
- Компилятор разрешает умолчание: в проводе у каждого run **явный** `type`.
- Списки отсортированы канонически.
- Хеш геометрии покрывает новые поля — он считается по отдаваемым байтам, так
  что это выполняется само; проверить мутационным тестом.
- `placement_algorithm` — строка версии, меняется при смене алгоритма.

### Task 4: Особенность крестовины

**Файлы:** изменить `track/compile.go`; тест `track/compile_test.go`.

**Produces:** поле `features` в `RenderGeometry`; вид `frog`.

**Критерии приёмки:**
- Форма ровно как в спеке §5: `owner`, `kind`, `point`, `addresses[]` с `u` и
  собственной `tangent` внутри каждого адреса.
- Пересекаются **две конкретные** нитки: при `hand="right"` — прямой проход
  `−gauge/2` с боковым `+gauge/2`, при `hand="left"` наоборот.
- `gauge` берётся из типа **самого устройства**.
- Ровно одно невырожденное пересечение; ноль, два и более, касание — отказ.
- Проверяемое следствие: для `ST_A_SW_1` (R=300, колея 1.435) крестовина
  попадает на `s ≈ 29.36 м` при длине бокового прохода 33.21 м. Тест обязан
  сверять это число с допуском 0.05 м.
- `switch_toe` и `switch_heel` НЕ отдаются: конец остряка сервер вывести не
  может (спека §5), действует клиентская эвристика.

### Task 5: Карта ST_A обретает конструкцию

**Файлы:** изменить `server/maps/st_a.json`; `mapfmt/limits.go`
(`FormatVersion`).

**Критерии приёмки:**
- `format_version` поднят до 2, `map_revision` до 3.
- Блок `construction` **порождён скриптом, а не набран руками**: по одному run
  на ребро с фазой 0, кроме пары `ST_A_E_E34` и `ST_A_E_T4`, которые стыкуются
  напрямую и сливаются в один run. Скрипт положить в `server/cmd/` или
  `tools/`, чтобы его можно было прогнать повторно.
- Два типа не требуются: достаточно одного, `TRACK_MAIN_1435`.
- Эталон `contract/render_geometry.golden.json` перегенерирован генератором.
- `go build ./... && go vet ./... && go test -count=1 ./...` зелёные.

## Волна 2b — клиент (после слияния 2a)

### Task 6: Константы уезжают в тип

**Файлы:** `client/scripts/world.gd`, `client/scripts/geometry_parser.gd`,
`client/tests/contract_check.gd`.

**Критерии приёмки:**
- `GAUGE_HALF`, `SLEEPER_STEP`, `SLEEPER_HALF`, `SLEEPER_WIDTH`,
  `BALLAST_HALF_W`, `PLATFORM_OFFSET`, `PLATFORM_WIDTH` заменены числами из
  типа.
- `FROG_WING` **остаётся** в клиенте — это стиль, а не факт (спека §2).
- Парсер знает `track_types`, `construction_runs`, `features`; неизвестный вид
  особенности — ошибка, а не пропуск.

### Task 7: Размещение по рецепту

**Файлы:** `client/scripts/world.gd`, `client/scripts/geometry_math.gd`.

**Критерии приёмки:**
- Шпалы ставятся по накопленной координате run, а не по локальному `u`.
- Правило полуоткрытое: `phase + n × pitch ∈ [0, run_length)`. Шпала в конечной
  точке больше не ставится принудительно.
- На стыке `ST_A_E_E34` с путём 4 сдвоенной шпалы нет; на остальных рёбрах
  расположение не изменилось.
- Позиция считается от аналитической `pose(u)`, не от тесселированной
  полилинии.
- Поперечная ось шпалы — по левой нормали.

### Task 8: Крестовина из особенности, `resample_uniform` не виснет

**Файлы:** `client/scripts/turnout_layer.gd`, `client/scripts/geometry_math.gd`,
`client/tests/test_geometry_math.gd`.

**Критерии приёмки:**
- Крестовина строится из особенности `frog`, а не из марки; марка показывается
  подписью, если есть.
- Карта без марки рисуется нормально.
- `resample_uniform` отвергает неположительный шаг вместо зацикливания; тест на
  `step = 0` и `step < 0` красный до правки.

## Что этот план сознательно НЕ делает

- Уровень 3 (стрелочные брусья, контррельсы, переопределения) — потребителя нет.
- Обобщение модели устройства — отложено, сегодня достаточно обычных стрелок.
- Глухое пересечение — гейт не снят.
- Вертикальный профиль в контракте — потребителя нет.
- Запись номера профиля валидации в манифест — после слияния обеих волн.
