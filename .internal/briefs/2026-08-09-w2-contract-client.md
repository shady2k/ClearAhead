# Бриф W2 — контрактная фикстура и все её потребители

Рабочий каталог: **`/home/dev/repos/ClearAhead`**. Сделай `pwd` первым делом.

## Почему ты владеешь и сервером, и клиентом

Предыдущий воркер расцепил Go-тесты с боевой картой `server/maps/st_a.json`,
пересобрав эталон `contract/render_geometry.golden.json` с новой фикстуры. Это было
вынужденно: `server/internal/httpapi/contract_test.go:130` сравнивает вывод сервера
с эталоном, а рендерится теперь фикстура.

Побочный эффект: **клиентский контракт сейчас красный**, и клиент вдобавок зашивает
идентификатор карты. Ты владеешь фикстурой и всеми, кто на неё смотрит, чтобы
миграция произошла один раз, а не тремя волнами правок.

## Что сделать

### 1. Обогатить фикстуру горловиной

`server/internal/mapfmt/testdata/fixture_station.json` сегодня содержит одну
стрелку, и в эталоне 5 элементов. Этого мало по двум причинам:

- баг `«шпальные решётки соседних элементов накладываются в горловине»` с такой
  фикстуры **не воспроизводится**, а он живой и его придётся ловить;
- клиентский контрактный тест покрывает меньше, чем покрывал на боевой карте.

Добавь **горловину: минимум две смежные стрелки, образующие съезд** между двумя
путями. Сохрани всё, что уже есть (дуга вне стрелки, платформа через `TrackSpan`,
`buffer_stop`, `map_boundary`, блок `construction`).

**Фикстура обязана остаться маленькой.** Нужна горловина, а не станция: если начнёт
разрастаться до четырёх путей и двух горловин — ты пошёл не туда. Она должна
проходить `mapfmt.Validate` и `track.Compile`.

### 2. Пересобрать эталон

`contract/render_geometry.golden.json` — с обогащённой фикстуры. Механизм записи
эталона уже есть в `contract_test.go` (см. `goldenPath` и запись файла рядом).

### 3. Сервер отдаёт манифест

`track.Manifest` уже несёт `map_id`, `map_revision` и хеши, но наружу они не
отдаются, и узнать текущую ревизию клиент не может — сервер отвечает 404 на всё,
кроме одной загруженной ревизии.

Добавь выдачу манифеста **через барьер `server/internal/protocol`**, а не мимо него.
Прочитай `protocol.go` целиком: там запечатанный интерфейс `Request[T]` с `Parse` и
`sealed`, и правило пакета — «у запроса, пришедшего снаружи, не существует
невалидного представления». Обходить барьер нельзя.

### 4. Клиент перестаёт зашивать карту и ревизию

`client/scripts/main.gd` держит `var _map_id := "ST_A"` и `var _revision := 1`.
**Оба исчезают.** Клиент берёт их из манифеста и только после этого запрашивает
геометрию.

Обработку отказа **не трогай** — она работает правильно: в интерфейсе «Сервер
ответил HTTP 404» и кнопка «Повторить». Дефект не в ней.

### 5. Мигрировать клиентские тесты на новый эталон

- `client/tests/contract_check.gd` — строка 32 проверяет `map_id == "ST_A"`; строки
  79 и 104 ссылаются на `ST_A_E_T2`/`ST_A_E_T3` и `RUN_ST_A_E_E34_T4`. Всего этого
  в новом эталоне нет.
- `client/tests/test_geometry_math.gd` — ссылается на `ST_A_E_W12`.
- `client/tests/test_draw_helpers.gd` — **не трогай**: он держит литералы внутри
  себя и от эталона не зависит.

Смысл проверок сохраняй, а не вырезай: если тест проверял, что спан платформы лежит
на конкретных элементах, он должен проверять то же самое на элементах фикстуры.
Удалить проверку вместо переноса — это отказ приёмки.

## Критерии приёмки

- фикстура содержит горловину минимум из двух смежных стрелок и остаётся маленькой
- в `main.gd` нет присвоения литерала ни для `map_id`, ни для ревизии
- `grep -n "ST_A" client/tests/*.gd` — пусто, кроме `test_draw_helpers.gd`
- ни одна проверка в клиентских тестах не удалена, все перенесены
- подъём ревизии карты не ломает клиента

## Проверка — только своя

```bash
cd /home/dev/repos/ClearAhead/server
go build ./internal/httpapi/... ./internal/protocol/... ./internal/mapfmt/... ./internal/track/...
go test ./internal/httpapi/... ./internal/mapfmt/... ./internal/track/...
```

Клиент:

```bash
cd /home/dev/repos/ClearAhead
DISPLAY=:1 godot --path client --script tests/contract_check.gd
```

**Godot проверяется снимком, а не логом.** Отказ HTTP приходит асинхронно и
обрабатывается штатно: в логе будет чисто, а на экране 404. Если нужен снимок:

```bash
DISPLAY=:1 godot --path client --script tests/smoke_screenshot.gd -- --shot /tmp/w2.png
```

`--headless` не рисует. Запускать только на `DISPLAY=:1`.

**Не запускай `go test ./...`, `go vet ./...`, форматтеры по всему репозиторию.**
Параллельно работают два других воркера. Полный прогон делает координатор в конце
эпика.

## Отчётность

```bash
orca orchestration send --type heartbeat --subject alive \
  --task-id <TASK_ID> --dispatch-id <DISPATCH_ID> --phase "<фаза>" --json

orca orchestration send --type worker_done --subject "<итог>" \
  --body "<что сделано, числа, что НЕ проверено>" \
  --task-id <TASK_ID> --dispatch-id <DISPATCH_ID> --outcome succeeded \
  --files-modified "<пути>" --json
```

В `worker_done` обязательно перечисли, **что осталось красным или непроверенным**.
Молчание об этом считается ошибкой отчёта.
