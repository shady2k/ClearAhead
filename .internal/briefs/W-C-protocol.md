## Что сделать
Задача 9 из `.internal/plans/2026-08-08-b1-server-half.md`. Полный код в плане.

Это **требование владельца проекта**, сформулированное дословно: «все внешние вызовы
должны валидироваться на бэке обязательно, нужно сделать так, чтобы было архитектурно
невозможно вызвать метод на бэке без валидации».

## Как устроен барьер — прочитай внимательно, это суть задачи
Механизм — **не** «не забыть позвать `Validate()` в начале обработчика». Вызов можно
забыть, и забудут: не в первом методе, а в двенадцатом.

Барьер строится по принципу *«разбирай, а не проверяй»*: **невалидного представления
входа не существует как значения**.

- Поля `protocol.GeometryRequest` неэкспортируемые. Заполнить их можно только методом
  `Parse`, а зовёт `Parse` только диспетчер.
- Интерфейс `protocol.Request[T]` **запечатан** неэкспортируемым методом `sealed()`.
  Реализовать его можно только внутри пакета `protocol`.
- `rpc.Register` принимает лишь типы, удовлетворяющие `Request`, то есть лишь те, у
  которых разбор есть. Обойти `Register` нельзя: `routes` неэкспортируемо.
- `Parse` экспортирован, потому что звать его должен диспетчер из другого пакета.
  Запечатанность держит `sealed()`, а не он. Не перепутай.

Пути в обработчик мимо разбора нет **не по соглашению, а потому что такое значение
неоткуда взять**.

## Тест барьера на AST
Второй слой: `barrier_test.go` обходит AST пакетов вне `internal/rpc` и падает, если
встречает `PathValue`, `Unmarshal`, `NewDecoder`, `ParseForm` — то есть чтение сырого
внешнего входа мимо барьера.

**Важно:** каталогов `internal/httpapi`, `internal/track` и `cmd` на момент твоей работы
может ещё не быть — их делают другие воркеры позже. `filepath.Glob` по несуществующему
каталогу вернёт пустой список без ошибки, тест просто пройдёт вхолостую. Это ожидаемо,
не считай это провалом и не создавай эти каталоги.
`internal/mapfmt` из проверки исключён сознательно: он разбирает файл карты с диска, а не
внешний вызов, и у него свой строгий разбор.

## Критерии приёмки
- Обработчик получает уже разобранный тип и не имеет доступа ни к сырым байтам, ни к пути.
- `TestDispatchParsesBeforeHandler`: на невалидной ревизии обработчик **не вызван вовсе** —
  проверяется счётчиком вызовов.
- `TestDispatchUnknownMethod`: неизвестный метод — ошибка, а не паника.
- `TestDispatchRejectsGarbageBody`: пустой `map_id` — отказ.
- Тест барьера написан и проходит.

## Проверка (строго эта, не шире)
```
go build ./internal/protocol/ ./internal/rpc/ && go vet ./internal/protocol/ ./internal/rpc/ && go test ./internal/rpc/ -v
```
В отчёте отдельно ответь: **можно ли в текущем коде зарегистрировать метод без разбора?**
Если да — где дыра. Это главный вопрос задачи, не отвечай на него «нет» не проверив.
