# Общие правила для всех воркеров волны В1

## Рабочее дерево
Твой рабочий каталог — **общий worktree** `/home/dev/repos/ClearAhead`, ветка `b1-server-half`.
Сначала выполни `pwd` и убедись. В этом же дереве параллельно работают другие воркеры.

## Владение файлами — жёстко
Ты правишь **только свои файлы**, перечисленные в твоём брифе. Файлы других воркеров
существуют, могут быть в полуготовом состоянии и **трогать их нельзя ни при каких
обстоятельствах**. Увидел ошибку в чужом файле — не чини, сообщи об этом в `worker_done`.

## Запрещено
- Коммитить, пушить, создавать ветки. Коммитит координатор.
- Запускать общерепозиторные проверки: `go build ./...`, `go test ./...`, `go vet ./...`.
  Они увидят полуготовые файлы соседей и дадут фантомные ошибки.
- Форматировать чужой код, запускать `gofmt`/`gofumpt` по репозиторию.
  `gofmt` по **своим** файлам — можно и нужно.
- Трогать трекер задач (`bd`). Беды принадлежат координатору.

## Обязательно
- Проверка **строго по своим пакетам**: `go build ./internal/<твой>/ && go vet ./internal/<твой>/ && go test ./internal/<твой>/`.
  Именно так, с явным путём пакета. Это не общерепозиторный гейт, это твой пакет.
- Heartbeat при каждой смене фазы:
  `orca orchestration send --type heartbeat --subject alive --task-id <TASK_ID> --dispatch-id <DISPATCH_ID> --phase "<фаза>" --json`
- Ровно один `worker_done` в конце:
  `orca orchestration send --type worker_done --subject "<итог>" --body "<что сделано, числа, что не проверено>" --task-id <TASK_ID> --dispatch-id <DISPATCH_ID> --outcome succeeded --files-modified "путь1,путь2" --json`
  При провале — `--outcome failed`. Не кодируй провал только прозой.
- Если что-то заблокировало — `orca orchestration ask --question "..." --timeout-ms 600000 --json`, не гадай.

## Отчёт
Числа, а не прилагательные: сколько тестов, сколько прошло, сколько строк. Обязательно
перечисли **что не смог проверить** и **что заметил, но намеренно не тронул**. Молчание в
этом разделе будет прочитано как «нечего сообщить» — не как «не проверял».
