## Корень дефекта
Сейчас поза хранится **на порт** плюс «владелец»:
```go
type portState struct { Pose PortPose; Owner string }
func (s portState) as(element string) PortPose { /* владелец — как есть, остальные — Reverse */ }
```
Это неоднозначно **физически**: у общего порта стрелки три инцидентности —
внешнее ребро и два прохода, — и одного направления на порт не хватает.
Проходы `C→S` и `C→D` смотрят в одну сторону, внешнее ребро — в другую.

Координатор пробовал починить это правилом «два прохода одной стрелки — одна
сторона» прямо в `as()`. **Не помогло: невязка выросла с 52 до 118 метров.**
Неоднозначность не исчезает, пока хранится одна поза на порт — она лишь
переставляется. Не повторяй этот путь.

## Требуемая структура
Хранить позу **инцидентности**, а отношения строить отдельной проверяемой фазой.

```go
type Incidence struct { Port, Element string }

type PortPose struct {
    Plan  geom.Pose
    Z     float64
    Slope float64 // dz/du в направлении Plan
}

type PortRelation struct {
    To   Incidence
    Flip bool // направления внутрь элементов различаются на π
}

type Junctions map[Incidence][]PortRelation
type IncidencePoses map[Incidence]PortPose

func buildJunctions(m *mapfmt.Map, elements map[string]Element) (Junctions, error)
func relate(p PortPose, flip bool) PortPose
func across(e Element, from Incidence, at PortPose) (Incidence, PortPose, error)
func settle(poses IncidencePoses, at Incidence, want PortPose) error
```

`buildJunctions` **утверждает** отношения, а не выводит их из порядка обхода:
```
обычный порт, два ребра:  edge1 --flip--> edge2
turnout.C:                straight --same--> diverging
                          external --flip--> straight
                          external --flip--> diverging
turnout.S:                external --flip--> straight
turnout.D:                external --flip--> diverging
```
и отвергает ноль либо больше одного внешнего ребра на любом порту стрелки.

`relate` при `flip`: `Plan = geom.Reverse(Plan)` **и `Slope = -Slope`**.

Алгоритм: якорь задаёт позу конкретной инцидентности → `across` переносит её
через элемент → `settle` сравнивает **одну и ту же инцидентность** (выбора
ориентации там больше нет) → по `Junctions` поза расходится на остальные
инцидентности того же порта через явный `Same`/`Flip`.

После этого сортировка влияет только на порядок диагностики, не на результат.

## Три дефекта, которые надо закрыть заодно
1. **Замыкание уклона не реализовано вовсе.** `TolSlope` объявлен, но `PortPose`
   не содержит уклона и `settle` его не сравнивает — заявленная спекой проверка
   не существует. Добавь `Slope` в `PortPose`, бери его из профиля и сравнивай.
2. **Валидатор допускает два внешних ребра на порту стрелки** (`used > 2`).
   На портах стрелки требуется **ровно одно** внешнее ребро. Обычный порт —
   по-прежнему до двух.
3. **Якорь на порту с несколькими инцидентностями неоднозначен.** Минимально
   честно: отказ, если у порта якоря больше одной инцидентности и не указан
   элемент. Формат якоря не меняй — просто отвергай неоднозначный случай.

## Тесты — обязательный минимум
1. Одна стрелка, внешнее ребро у `C` имеет `To == C` — компилируется.
2. Та же геометрия, ребро развёрнуто (`From == C`) — результат геометрически тот же.
3. На `C` первым по сортировке становится по очереди `straight`, `diverging`,
   внешнее ребро — результат не меняется.
4. Переименование элементов, меняющее порядок сортировки, не меняет стартовые
   позы в пределах допуска.
5. `straight` и `diverging` в `C` получают одинаковый heading; внешнее ребро — +π.
6. Валидатор отвергает два внешних ребра на порту стрелки.
7. Якорь на многозначном порту отвергается.
8. Замыкание уклона: согласованный принимается, зонды по обе стороны `TolSlope`.
9. `TestStationCompiles` остаётся приёмочным.

Существующие `TestPropagateClosureMismatch` и `TestPropagateClosureWithinTolerance` —
зонды по обе стороны допуска положения, **должны остаться и пройти**.

## Чего делать нельзя
- Ослаблять любой допуск. Тянет ослабить — чинишь не то.
- Править карту.
- Канонизировать ориентацию стрелки в формате: обе законны, требование «общий
  порт всегда `To`» замаскировало бы дефект.

```
cd server && go build ./... && go vet ./internal/track/ ./internal/mapfmt/ && go test ./internal/track/ ./internal/mapfmt/ -v
```
всё зелёное, **включая `TestStationCompiles`**, без единой правки карты.

Если после починки кода карта всё ещё не сходится — **сообщи невязку и не трогай
карту**. Подозрительное место: у `ST_A_E_E12` порядок звеньев `arc, straight`,
тогда как на западе тот же узор записан `straight, arc`; это следы правки
предыдущего воркера. Но решать это будем после того, как код станет верным.
