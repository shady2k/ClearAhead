# Общие правила воркеров эпика ClearAhead-sqym

## Рабочее дерево

Твой рабочий каталог — **общий worktree** `/home/dev/repos/ClearAhead`, ветка
`b1-server-half`. Сначала выполни `pwd` и убедись. В этом же дереве параллельно
работают другие воркеры.

Go-модуль лежит в `server/`, модуль `github.com/shady2k/ClearAhead`, Go 1.26,
только стандартная библиотека. Команды `go` запускай из `/home/dev/repos/ClearAhead/server`.

## Владение файлами — жёстко

Ты правишь **только свои файлы**, перечисленные в твоём брифе. Файлы других
воркеров существуют, могут быть в полуготовом состоянии, и **трогать их нельзя
ни при каких обстоятельствах**. Увидел ошибку в чужом файле — не чини, сообщи в
`worker_done`.

## Запрещено

- Коммитить, пушить, создавать ветки. Коммитит координатор.
- Общерепозиторные проверки: `go build ./...`, `go test ./...`, `go vet ./...`,
  `gofmt` по репозиторию. Они увидят полуготовые файлы соседей и дадут фантомные
  ошибки. `gofmt` по **своим** файлам — можно и нужно.
- Трогать трекер задач (`bd`). Беды принадлежат координатору, и в этом worktree
  база трекера всё равно не отвечает: вся приёмка — в брифе и в плане.

## Обязательно

- Проверка **строго по своим пакетам**, с явным путём:
  `cd /home/dev/repos/ClearAhead/server && go build ./internal/<твой>/ && go vet ./internal/<твой>/ && go test ./internal/<твой>/`
- Heartbeat при каждой смене фазы (IDs возьми из своей преамбулы диспатча):
  `orca orchestration send --type heartbeat --subject alive --task-id <TASK_ID> --dispatch-id <DISPATCH_ID> --phase "<фаза>" --json`
- Ровно один `worker_done` в конце:
  `orca orchestration send --type worker_done --subject "<итог>" --body "<что сделано, числа, что не проверено>" --task-id <TASK_ID> --dispatch-id <DISPATCH_ID> --outcome succeeded --files-modified "путь1,путь2" --json`
  При провале — `--outcome failed`. Не кодируй провал только прозой.
- Заблокировало — `orca orchestration ask --question "..." --timeout-ms 900000 --json`, не гадай.

## Стиль проекта — это не украшение

- **Идентификаторы английские. Комментарии, документация и тексты отказов —
  русские.** Имя теста — идентификатор, значит английское. Строка внутри
  `fmt.Errorf` — русская, её читает человек.
- **Комментарий объясняет ПОЧЕМУ:** причину решения, его цену, что отвергнуто.
  Не пересказ кода. Образец — `server/internal/chunk/chunk.go`,
  `server/internal/worldgen/worldgen.go`.
- **Валидатор отказывает, а не чинит.** Молчаливая подстановка запрещена.
- **Числа — замером, а не рассуждением.** Оценка называется оценкой, замер —
  замером, и в комментарии видно, что именно. Этот эпик заведён в том числе
  потому, что автор спеки процитировал отозванное число.
- **Float64 не сверяется байт в байт** — допуск либо округление до объявленной
  точности.
- **Не заводить полей «на будущее»:** форма без потребителя окажется неверной.
