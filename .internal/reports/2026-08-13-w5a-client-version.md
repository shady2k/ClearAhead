# W5-A — клиент: накопление версии и атомарное переключение видимого набора

Дата: 2026-08-13. Ветка `b1-server-half`. Бида: ClearAhead-sqym.6.
Файлы: `client/scripts/version_set.gd` (новый), `client/scripts/world_api.gd`,
`client/scripts/world.gd`, `client/tools/checks/pure/90_version_set.gd` (новый),
`client/tools/checks/live/35_worlds.gd` (новый), `client/tools/checks/live/00_manifest.gd`.

## Что сделано

**VersionSet (`client/scripts/version_set.gd`)** — чистый накопитель ОДНОЙ
версии мира: сеть + патчи фиксированного списка чанков (те, что в памяти).
Правила, которые нельзя переоткрывать:

- **Приём по версии.** Каждый ответ принимается только с версией набора;
  опоздавший ответ старой версии — мусор (патчи разных версий не коммутативны,
  спека §5.1). Ответ клетки ВНЕ набора валит набор — смешение двух наборов
  невозможно молча.
- **Повтор — no-op.** Первый ответ клетки окончателен (адрес immutable);
  повтор того же патча ничего не меняет. Другая клетка набор меняет —
  идемпотентность про ту же клетку той же версии.
- **204 — полный ответ** («чистая база»): делает набор готовым так же, как 200,
  не ошибка, не переспрашивается. Отказ (транспорт/404) набор НЕ делает
  готовым — он падает, видимой остаётся старая версия целиком.
- **commit() отдаёт набор целиком** — применять его можно только одним шагом.

**WorldApi** — версионные адреса контракта (sqym.5): `world_network(match, v)`,
`world_patch(match, v, level, cx, cz)` (200 → have(), 204 → `no_work()` —
чистая база, прочее → failed()), `world_tile`/`world_terrain` (патч из
версионного адреса, покров и лес — из неверсионного: у версионного адреса их
нет, они производные рецепта, не земляных работ). `Tile.heights` разтипизирован
(Heights на неверсионном проводе, Patch на версионном — один протокол).

**world.gd** — фиксированная версия и атомарное переключение:

- Манифест читает `projection_head.world_version` → `_fixed_version`; без неё —
  отказ (версионные адреса не собрать). Матч берётся из живого состояния
  РАНЬШЕ сети (версионные адреса идут через `/matches/{m}/`), и живой ответ
  передаётся в `_load_rolling_stock` — второго запроса нет.
- Сеть и патчи всех новых чанков спрашиваются ТОЛЬКО у `_fixed_version`
  (`world_network`, `world_terrain`) — «новые чанки камеры спрашиваются у
  зафиксированной версии». 204 в начальной загрузке — то же, что «чанка нет»
  сегодня: клетки вне материализованного мира нет на этом уровне, место
  остаётся за грубым; не ошибка, не ретрай.
- Опрос головы (`_head_poll`, 5 с) замечает новую версию; `VersionSet` копит
  сеть + патчи чанков в памяти; по готовности `_apply_version_set` переключает
  видимый набор ОДНИМ синхронным проходом: путь (снят старый Track, нарисован
  новый), ось и маска балласта, высоты в уже стоящие узлы (`_swap_terrain_heights`,
  меши пересобираются на месте, структура узлов не трогается), растительность и
  трава (сидят на высотах), твердь (коллизии якорей пересоздаются). Человек
  переставляется на элемент новой сети.
- Цена прохода замеряется: `version_switch_ms` + разбивка по фазам — в HUD и в
  отчёте (перестройка мешей под кадровым бюджетом — sqym.7).

## Цена переключения кадру

Не замерена на живой второй версии: сервер не умеет публиковать вторую версию
(журнал всегда 0, мутации — соседний edit-пакет в работе). Из чистых тестов и
строения прохода оценка не даётся; в отчёте клиента число появится с первой
публикацией. Замерено по фазам внутри `version_switch_breakdown` — это и есть
то, что переключение подкидывает кадру.

сервера: мир загружен ПОД ЗАФИКСИРОВАННОЙ ВЕРСИЕЙ — в отчёте `world_version 1`,
`chunks_requested 80, chunks_got 80, chunks_absent 0, chunks_orphaned 0`;
снимок сохранён (1600×900, ~1.7 МБ), ASCII-классификация кадра: слева панель
HUD, справа луг с тёмной структурой пути — мир нарисован. Террейн 66.6 с —
НЕ сервер: версионный патч отвечает за 0.6 мс (замер curl, 8450 Б), т.е. это
серийная выборка 240 запросов, ждущих кадр llvmpipe (известная цена s42, не
этой правки).

## Что не смог проверить снимком

**Атомарное ПЕРЕКЛЮЧЕНИЕ версии на живом сервере — не проверено.** Сервер
сегодня не публикует вторую версию (журнал всегда 0, бида sqym.5; публикации —
соседний `server/internal/edit` в работе). Проба: scratch-Go-публикация v2
(поднят блок клеток чанка 0/0/0 на 5 м) на scratch-базе УСПЕШНА — голова
стала 2, `network_version` не тронут, патч `/worlds/2/…` отдаёт 200 за 0.6 мс —
но клиентский переключатель на ней не гонялся (убрано по правилу владения:
транзиентный файл в server/ вне моих файлов). Семантика переключения покрыта
чистыми проверками набора + живым договором версионных адресов; проход
`_apply_version_set` проверится с первой реальной публикацией.
